# Shell NFT DAPP

A reproducible Shell-native NFT dApp for testing Shell Chain smart contract deployment and interaction.

This example stores Shell-native owners as Solidity `bytes32`, preserving all
32 bytes of their canonical address. Standard Solidity `address` is 20 bytes;
SDK encoding cannot widen the compiler's address decoder or storage layout.
The contract targets Cancun instructions supported by the node.

The example ABI uses `mint(bytes32,string)`, `ownerOf(uint256) returns (bytes32)`
and `TransferShell(bytes32,bytes32,uint256)`. Redeploy the example after this ABI
change; contracts compiled with the earlier `address` owner ABI are incompatible.

The scripts and browser UI use the public `shell-sdk/contracts` APIs for
compile, deploy, write, read, and receipt handling. The lockfile installs the
published `shell-sdk@0.13.0` package, so a standalone checkout can install and
compile without a sibling SDK repository.

### Node compatibility

The published SDK 0.13.0 signs V1 transactions. Current node source expects V2,
so compilation and browser builds do not establish deploy/mint compatibility.
Use a compatible SDK and node pair before running the transaction flow; a
compatible public SDK release is still required for that standalone path.

For source development, build a compatible SDK in a sibling checkout and then
replace only the local installed dependency, preserving the committed lockfile:

```bash
npm ci
npm install --no-save --package-lock=false ../shell-sdk
```

Record the SDK and node commits used for the smoke run. A source override is
not evidence that the published-package tutorial passes.

## Prerequisites

- Node.js 20+
- A running Shell Chain node at `http://127.0.0.1:8545`
- A funded Shell keystore generated by `shell-node key generate`

Start the local node with CORS enabled for the browser UI:

```bash
shell-node run \
  --datadir shell-data \
  --keystore my-key.json \
  --password-file .quickstart-password \
  --rpc-addr 127.0.0.1:8545 \
  --rpc-cors "http://127.0.0.1:5173,http://localhost:5173" \
  --block-time 2000 \
  --max-idle-interval 0 \
  --network dev \
  --rpc-api eth,net,web3,shell
```

## Setup

```bash
npm ci
cp .env.example .env
```

Edit `.env`:

```bash
SHELL_RPC_URL=http://127.0.0.1:8545
SHELL_CHAIN_ID=1337
SHELL_KEYSTORE_PATH=../shell-chain/my-key.json
SHELL_KEYSTORE_PASSWORD=dev-password
NFT_BASE_URI=ipfs://example/
```

## CLI flow

```bash
npm run compile
npm run smoke
```

The smoke test deploys `ShellNft`, mints token `1` to the signer address, then verifies `totalSupply`, `ownerOf(1)`, and `tokenURI(1)` through `eth_call`.
All of those actions go through `shell-sdk/contracts` rather than local
transaction-building or ABI plumbing.
The smoke run also checks the full owner in the mint event, rejects empty-URI
and zero-owner mints, and verifies that those failures preserve NFT state.

Individual commands:

```bash
npm run deploy
npm run mint -- ipfs://example/shell-nft-1.json
npm run read -- 1
```

## Browser flow

```bash
npm run compile
npm run dev
```

Open `http://127.0.0.1:5173`, paste your keystore JSON, password, and compiled bytecode from `artifacts/ShellNft.compiled.json`, then deploy and mint.
